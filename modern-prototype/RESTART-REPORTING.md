# Restart reporting preference

User instruction, 2026-09-11: every server restart must be followed by a full report.

Announce the planned restart beforehand. After it finishes, report why it restarted; the exact changes deployed and how to use them; clean-save and backup status; build, regression and authenticated login results; whether the server is online; and known limitations or unfinished work. Clearly distinguish new changes from earlier deployments. If a restart fails, report the failure and current server state promptly. Do not claim client visual verification or gameplay tests that were not performed.
